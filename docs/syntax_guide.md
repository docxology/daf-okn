# Syntax Guide

This document defines the syntax conventions for documentation and manuscript content inside the daf-okn project. Rules 1–5 are mandatory constraints; sections 6–8 are reference material for common operations.

---

## 1. Markdown Links

Hyperlinks must be informative. Never use placeholder text.

- **BAD**: [this link](https://okn.us/) to see the registry.
- **GOOD**: See the [OKN registry](https://registry.okn.us/).

For internal cross-references inside `manuscript/`, prefer relative paths:
- **BAD**: See `https://github.com/docxology/daf-okn/blob/main/src/daf_okn/core/registry.py`
- **GOOD**: See [`src/daf_okn/core/registry.py`](https://github.com/docxology/daf-okn/blob/main/src/daf_okn/core/registry.py)

---

## 2. Pandoc-Crossref Cross-References

Inside `manuscript/` files, use Pandoc-crossref `[@label]` syntax for
cross-referencing. **Never** use raw LaTeX `\ref{}` macros in Markdown
source — they would render literally in HTML output and
they bypass Pandoc-crossref's auto-numbering. Never hardcode figure or
table numbers.

- **BAD**: See Table 1 or Figure 2.
- **BAD**: See Table `\ref{tbl:graph_metrics}` or Figure `\ref{fig:cognitive_network}`.
- **GOOD**: See [@tbl:graph_metrics] or [@fig:cognitive_network].

### Figure Label Registry

Both figures generated by `src/daf_okn/figures/` (orchestrated via `scripts/10_research_workflow.py`) use these labels:

| Anchor (in `03_results.md`) | PNG Filename | Generator Function |
|---|---|---|
| `{#fig:registry_catalog}` | `output/figures/registry_catalog.png` | `plot_graph_catalog()` |
| `{#fig:cognitive_network}` | `output/figures/cognitive_network.png` | `plot_network()` |

The table anchor used in `03_results.md`: `{#tbl:graph_metrics}`.

## 3. Variable Injection (Madlibs)

When specifying numeric results in the manuscript, use the `{{VARIABLE_NAME}}` syntax. Values are computed by `src/daf_okn/core/manuscript_variables.py::generate_variables()` and written to `output/data/manuscript_variables.json` by the thin orchestrator `scripts/z_generate_manuscript_variables.py`. Never hardcode a number that will change when the underlying graph data changes.

- **BAD**: The graph contains 1,204 nodes.
- **GOOD**: The graph contains `{{NODE_COUNT}}` nodes.

### {{VARIABLE}} Token Reference

> The authoritative list of substitution tokens is the return value of
> `src/daf_okn/core/manuscript_variables.py::generate_variables()`, declared in
> the `variables:` block of `manuscript/config.yaml`. The regression
> test `tests/core/test_manuscript_variables.py::test_all_manuscript_tokens_are_generated`
> reads every `manuscript/*.md` file and fails CI on any token used in prose
> that the generator does not emit. **Treat the generator function — not this
> table — as the single source of truth**.

**CONFIG_* — Derived from `manuscript/config.yaml`**

| Token | Source |
|---|---|
| `{{CONFIG_TITLE}}` | `paper.title` |
| `{{CONFIG_SUBTITLE}}` | `paper.subtitle` |
| `{{CONFIG_VERSION}}` | `paper.version` |
| `{{CONFIG_FIRST_AUTHOR}}` | `authors[0].name` |
| `{{CONFIG_KEYWORDS}}` | `keywords` (comma-joined) |

**GRAPH_* — Derived from `output/data/graph_report.json`**

| Token | Source |
|---|---|
| `{{GRAPH_NAME}}` | `graph_report.graph_name` |
| `{{NODE_COUNT}}` | `graph_report.metrics.node_count` |
| `{{EDGE_COUNT}}` | `graph_report.metrics.edge_count` |
| `{{DENSITY_PCT}}` | `graph_report.metrics.density × 100` |
| `{{WEAKLY_CONNECTED_COMPONENTS}}` | `graph_report.metrics.weakly_connected_components` |
| `{{STRONGLY_CONNECTED_COMPONENTS}}` | `graph_report.metrics.strongly_connected_components` |
| `{{MEAN_DEGREE}}` | `graph_report.metrics.mean_degree` |
| `{{TRIANGLE_COUNT}}` | `graph_report.metrics.triangles` |
| `{{TOP_NODE_LABEL}}` | `graph_report.metrics.top_central_nodes[0][0]` |
| `{{TOP_NODE_CENTRALITY}}` | `graph_report.metrics.top_central_nodes[0][1]` |

**PROVENANCE_* — Computed at generation time**

| Token | Source |
|---|---|
| `{{CONFIG_HASH}}` | SHA-256 of `manuscript/config.yaml` (truncated) |
| `{{GENERATION_TIMESTAMP}}` | Generation time / `SOURCE_DATE_EPOCH` |
| `{{PYTHON_VERSION}}` / `{{PLATFORM}}` | Runtime |
| `{{NETWORKX_VERSION}}` / `{{MATPLOTLIB_VERSION}}` | Runtime |

**Zero-fabrication rule**: result-derived tokens show real values only after
`output/data/graph_report.json` exists (pipeline mode); draft runs
(`--allow-draft`) display `N/A` sentinels.

### Adding a New Variable

1. Add a key/value pair to `generate_variables()` in `src/daf_okn/core/manuscript_variables.py` and declare it in the `variables:` block of `manuscript/config.yaml`.
2. Add a corresponding test assertion in `tests/core/test_manuscript_variables.py` (the live cross-reference test `test_all_manuscript_tokens_are_generated` will catch any gap automatically).
3. Verify it produces a non-empty string: `uv run python scripts/z_generate_manuscript_variables.py && python -c "import json; d=json.load(open('output/data/manuscript_variables.json')); print(d['MY_TOKEN'])"`.
4. Reference it in a manuscript `.md` file as `{{MY_TOKEN}}`.

### Detecting Unresolved Tokens

If a token remains unresolved, the literal `{{TOKEN_NAME}}` will appear in the rendered output. Detect before rendering:

```bash
# Replace <rendered-dir> with wherever your toolchain writes substituted Markdown
grep -r "{{" <rendered-dir>/ 2>/dev/null \
  && echo "UNRESOLVED TOKENS FOUND" || echo "All tokens resolved"
```

## 4. Code Blocks

Always tag code blocks with their language identifier. This is required for Pandoc syntax highlighting.

```python
def example() -> bool:
    return True
```

For shell commands:
```bash
uv run pytest tests/ -v
```

For inline code referencing file paths, use single backticks: `src/daf_okn/core/registry.py`

---

## 5. Table Captions (Pandoc)

When writing tables in the manuscript, place the caption below the table using Pandoc syntax. The `\label{}` must be inside the caption line:

```markdown
| Quantity | Value |
|-----------|-----------|
| Nodes     | {{NODE_COUNT}} |
| Edges     | {{EDGE_COUNT}} |

: Structural metrics of the analyzed graph. {#tbl:graph_metrics}
```

Do not use `Table:` prefix — Pandoc infers the type from placement. Do
not hardcode the table number in text; always use `[@tbl:graph_metrics]`.

## 6. Adding a New Figure

To add a figure that appears in `03_results.md`:

1. Add the builder function to `src/daf_okn/figures/` and wire it through the workflow script (`scripts/10_research_workflow.py`).
2. Add the Pandoc image reference in `03_results.md`:
   ```markdown
   ![Caption text describing the figure.](../output/figures/registry_catalog.png){#fig:new_label}
   ```
3. Reference in text using Pandoc-crossref: `See [@fig:new_label].`
4. Update `manuscript/SYNTAX.md` to document the new figure label and generator.
5. Re-run the workflow and re-render to verify the figure appears.

## 7. LaTeX Math in Manuscript

Use `$...$` for inline math and `$$...$$` for display equations. Pandoc converts these to LaTeX automatically.

For numbered, referable equations, either attach a Pandoc-crossref anchor
with `{#eq:label}` directly after the closing `$$`, or use a LaTeX
`\begin{equation}...\label{eq:label}...\end{equation}` block (the
manuscript's 02_methodology.md and 03_results.md use this latter form for
`eq:` labels). Both forms are recognised by Pandoc-crossref; reference either
with `[@eq:label]`.

```markdown
\begin{equation}
\label{eq:density}
d = \frac{m}{n\,(n-1)}
\end{equation}
```

Reference in text: `[@eq:density]`. The registered equation labels live in
`manuscript/SYNTAX.md` (`eq:density`, `eq:mean_degree`).
