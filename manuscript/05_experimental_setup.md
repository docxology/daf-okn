# Experimental Setup {#sec:experimental_setup}

This section documents the configuration and the execution order that produced the artifacts behind [@sec:results]. Every parameter value below is either a `{{TOKEN}}` generated by `generate_variables()` or a field of [`manuscript/config.yaml`](config.yaml) (its `variables:` block is a reference map of each manuscript token and its source). No value is hardcoded in prose.

## Configuration surface

- **`manuscript/config.yaml`** — paper metadata (title, subtitle, version, authors, keywords) read by `src/daf_okn/core/manuscript_variables.py` for the `CONFIG_*` tokens; the `variables:` block is a reference map of the token inventory.
- **`output/data/graph_report.json`** — the analysis report written by `run_analysis` (schema in [@sec:methodology]); the source of all graph-metric tokens.
- **`output/data/registry_snapshot.yaml`** — the `kgs.yaml` snapshot written by the `pull_registry` stage; the source for the catalog figure.

## Workflow ordering

The workflow (`scripts/10_research_workflow.py`) chains the stages in-process, in this order:

1. `pull_registry` — `OKNRegistry.list_graphs()` snapshots the 45-graph catalog to `output/data/registry_snapshot.yaml` (network stage: fetches the live `kgs.yaml`; a local snapshot can be passed to `scripts/pull_registry.py --kgs-path` for offline use).
2. `export_cognitive` — `export_cognitive_kb` converts the `cognitive` vault (root from `--cognitive-repo` or `$DAF_OKN_COGNITIVE_REPO`) to `output/data/cognitive_kg.json`; skipped by design when no vault root is configured.
3. `analyze_graph` — `run_analysis` measures the exported document and writes `output/data/graph_report.json`.
4. `visualize` — `plot_graph_catalog` and `plot_network` render `output/figures/registry_catalog.png` and `output/figures/cognitive_network.png`.
5. `z_generate_manuscript_variables.py` — writes `output/data/manuscript_variables.json` from config + report (pipeline mode by default; `--allow-draft` for sentinel runs). It also writes token-substituted copies of the chapters to `output/manuscript/`; rendering them is left to the reader's own Markdown/Pandoc toolchain.
6. `09_provenance_record.py` — packages the analyzed graph and records the hashed receipt (run after analysis; independent of the manuscript variables).
